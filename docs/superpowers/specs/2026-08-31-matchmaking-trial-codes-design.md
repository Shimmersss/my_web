# 婚恋报告一次性内测邀请码设计

## 目标

为婚恋定位体检增加不注册、不登录的内测入口。root 在后台生成一枚独立的婚恋内测邀请码，访客凭邀请码免费完成一份包含可选伴侣画像的完整报告。生成失败可在同一访客身份下重试；成功后不能再次生成，但在报告可用期内可在其他设备重新输入原邀请码查看结果。

该功能不得把内测访客变成普通注册用户，不得让访客访问翻译、PPT、生图、留言板、通知、签到或后台等受保护能力，也不得改变正式用户现有的积分、任务、报告和权限流程。

## 已确认的产品规则

- 婚恋内测邀请码与账号注册邀请码是两类不同凭证，互相不可替代。
- 每枚内测邀请码只允许成功生成一份报告。
- 访客可以选择是否生成伴侣画像；两种情况都免费，不扣积分。
- 校验失败、队列已满、服务重启中断或模型生成失败不会消耗最终使用次数；已绑定的访客可继续重试。
- 首次兑换后邀请码绑定一个内部访客身份，不能转移成另一份生成资格。
- 成功后再次输入原邀请码只恢复查看权限，不再提供生成按钮。
- 原邀请码可在其他浏览器或设备上重新兑换，因此它在报告有效期内等同于查看凭证，页面必须提示妥善保管。
- 邀请码默认在创建后 7 天内完成首次兑换，root 可在生成时修改截止时间。
- 一旦首次兑换成功，兑换截止时间不再阻止同一邀请码恢复会话；但 root 撤销邀请码后，所有新旧会话都停止访问。
- 报告写入 30 天到期时间，并继续遵循后台现有的婚恋报告每用户及全站数量上限，因此用户文案使用“最长保留 30 天”。
- 报告过期、被用户删除或被保留上限清理后，不恢复生成资格。

## 方案选择

### 采用：受限访客身份复用现有任务与报告链路

首次兑换时创建一个内部 `MATCHMAKING_TRIAL` 用户和正常的 HttpOnly 会话。婚恋任务、资料和报告继续使用现有 `user_id` 外键、CSRF、防并发、磁盘任务快照和 30 天清理逻辑。新增的内测状态表负责邀请码绑定、免费资格和任务状态机。

该方案能复用已经验证的报告归属隔离，同时通过专用角色阻止访客进入其他功能。内部访客从后台注册用户列表、用户统计、签到榜和普通额度管理中排除。

### 不采用：独立匿名任务与报告表

这会要求婚恋任务、报告查询、root 全局查看、删除、清理和恢复逻辑维护第二套所有权模型，改动面更大且容易与正式用户行为漂移。

### 不采用：用现有注册邀请码自动创建普通账号

该方案会污染注册用户列表，并让匿名体验拥有普通用户身份，无法满足“只可使用一次婚恋测试”的权限边界。

## 数据模型

新增 `matchmaking_trial_codes` 表：

| 字段 | 含义 |
| --- | --- |
| `id` | 自增主键 |
| `code_hash` | 规范化邀请码的 SHA-256，唯一；数据库不保存原始邀请码 |
| `code_suffix` | 最后四位，仅供 root 列表识别和日志审计 |
| `guest_user_id` | 首次兑换后绑定的内部访客用户，唯一，可空 |
| `status` | `UNUSED`、`CLAIMED`、`RUNNING`、`RETRYABLE`、`COMPLETED` |
| `active_task_id` | 当前生成任务 ID，可空 |
| `report_id` | 成功报告 ID，可空 |
| `enabled` | root 是否允许兑换和恢复访问 |
| `expires_at` | 首次兑换截止时间，默认创建后 7 天 |
| `redeemed_at` | 首次兑换时间 |
| `completed_at` | 成功生成时间 |
| `created_by` | 创建该码的 root 用户 |
| `created_at`、`updated_at` | 审计时间 |

原始邀请码使用密码学安全随机数生成，展示形式为 `MM-` 加不少于 120 bit 随机强度的易复制大写字符串。后台只在创建响应中返回完整邀请码，之后的管理列表只显示后四位，避免数据库或后台截图泄露可直接查看报告的凭证。

首次兑换时，在同一事务中锁定邀请码记录、创建 `users.role='MATCHMAKING_TRIAL'` 的内部用户、写入绑定关系并把状态改为 `CLAIMED`。内部用户名不可由访客选择，密码使用随机不可见值生成 BCrypt，因而访客不能通过普通登录接口登录该身份。

现有数据库由显式迁移创建新表和索引；`schema.sql` 同时包含幂等建表定义，兼容生产 MySQL 和测试 H2。

## 状态机与并发规则

```text
UNUSED --首次兑换--> CLAIMED --提交并成功入队--> RUNNING --生成成功--> COMPLETED
                                |                    |
                                | 同步/队列失败      | 模型失败、保存失败、重启中断
                                v                    v
                            CLAIMED              RETRYABLE
                                                     |
                                                     +--再次提交--> RUNNING
```

- `UNUSED` 只有在 `enabled=true` 且未超过首次兑换截止时间时可兑换。
- `CLAIMED` 和 `RETRYABLE` 可以提交；状态更新使用带旧状态条件的原子更新，确保并发请求只有一个获得资格。
- 资料校验在占用资格前完成。任务成功放入队列后才进入 `RUNNING`。
- 队列拒绝、同步创建失败和持久化前失败将状态恢复为 `RETRYABLE`。
- worker 失败及启动恢复认定的中断任务将状态改为 `RETRYABLE`，不产生积分退款，因为内测任务从未扣分。
- worker 报告落库后，在任务标记完成的同一成功路径写入 `COMPLETED` 和 `report_id`。
- `COMPLETED` 永远不能回到可提交状态。报告不存在时只返回“报告已过期或已删除”。
- 重复输入已绑定的邀请码不会创建第二个内部用户，而是为同一个 `guest_user_id` 创建新的安全会话。

## 认证与权限隔离

内测访客使用现有 `rd_session` HttpOnly、SameSite=Lax Cookie 和 CSRF token，跨设备重新兑换会新增一条属于同一内部访客的会话。

`AuthService.currentUser` 可以识别内测访客，以便 `/api/auth/me` 和前端恢复状态；现有通用 `requireUser` 必须拒绝 `MATCHMAKING_TRIAL` 角色。新增仅供婚恋控制器调用的受限访问方法，接受正式 USER、ROOT 和状态有效的 MATCHMAKING_TRIAL。这样所有现有受保护控制器默认继续拒绝内测访客，无需逐个修改。

每次内测访客访问婚恋任务或报告接口时，后端都检查绑定邀请码仍为 `enabled=true`。root 撤销邀请码后，已有 Cookie 也不能继续读取报告。正式用户仍受现有节目可见性配置约束；内测邀请码是 root 主动发放的专项授权，因此不受 `Matchmaking=USER/ROOT` 的普通节目可见性限制。

兑换失败统一返回“内测邀请码无效、已过期或已撤销”，不泄露邀请码是否存在、是否被使用或具体状态。日志只记录邀请码后四位、内部 ID 和短错误，不记录完整邀请码或问卷内容。

## 后端接口

### root 管理

- `POST /api/admin/accounts/matchmaking-trial-codes`
  - 请求：`{ "expiresAt": "可选 ISO 时间" }`
  - 默认过期时间：服务器当前时间加 7 天。
  - 响应包含本次唯一一次展示的完整 `code`，以及管理摘要。
- `PATCH /api/admin/accounts/matchmaking-trial-codes/{id}`
  - 请求：`{ "enabled": true|false, "expiresAt": "可选 ISO 时间" }`
  - 允许调整未兑换码的截止时间和撤销/恢复；已兑换码的 `expiresAt` 仅作审计显示，恢复权限由 `enabled` 控制。
- 后台 dashboard 响应增加最近 100 条内测邀请码摘要：ID、后四位、状态、是否启用、首次兑换截止时间、兑换/完成时间、报告 ID。

不提供删除接口，保证已发放凭证和报告归属可审计。

### 访客兑换

- `POST /api/matchmaking/trial/redeem`
  - 请求：`{ "code": "MM-..." }`
  - 首次兑换绑定访客；再次兑换恢复同一访客。
  - 响应设置 `rd_session` Cookie，并返回 CSRF token、受限用户摘要及 trial 状态。
  - 若状态为 `COMPLETED` 且报告仍存在，响应包含 `reportId`，前端直接进入报告。

### 婚恋现有接口

现有 `/api/matchmaking/status`、`/reports`、`/tasks`、`/tasks/{id}` 和 `/reports/{id}` 接受有效内测访客，并仍按 `user_id` 隔离。`POST /reports` 根据角色分流：正式用户沿用积分预扣/退款；内测访客走一次性资格状态机且费用为 0。内测访客不能调用批量删除全部资料；单份报告删除继续允许，并明确提示删除后不能重新生成。

## root 全局报告展示

root 的全站报告查询左连接 `matchmaking_trial_codes`。普通报告继续显示用户名；内测报告显示 `内测访客 · ****1234`，不暴露内部随机用户名。root 仍只能删除自己的报告，不能删除正式用户或内测访客报告。

## 前端体验

### 未登录入口

`/matchmaking-report` 允许未登录访问。问卷前显示独立的“婚恋内测”入口卡：

- 输入婚恋内测邀请码并点击“开始一次内测”；
- 提供“已有账号，登录使用”的次入口；
- 说明包含完整报告和可选伴侣画像、失败可重试、成功后不可再次生成、邀请码可恢复查看、报告最长保留 30 天；
- 未兑换前不加载受保护的任务、状态和报告接口，也不展示可提交问卷。

兑换成功后刷新 auth store，再加载现有问卷和任务区域。`CLAIMED/RETRYABLE` 展示问卷；`RUNNING` 展示现有进度卡；`COMPLETED` 自动跳转报告；报告已不存在则展示不可恢复的过期/删除说明。

### 路由和共享顶栏

路由守卫只对婚恋入口放行未登录访问。婚恋报告详情仍要求正式或内测会话；未带会话直接访问详情时回到婚恋入口，兑换成功后按服务端返回的 `reportId` 恢复。

auth store 增加 `isMatchmakingTrial`。内测访客在共享顶栏显示“婚恋内测”与“退出”，不显示 credits、签到和通知；桌面和手机菜单只显示公开入口及婚恋报告，不显示其他 USER 能力。前端限制只改善体验，真正权限由后端 `requireUser` 隔离保证。

### 后台管理

后台新增“婚恋内测邀请码”面板，和账号注册邀请码分开：

- 截止时间默认 7 天后；
- 生成后立即复制完整邀请码，并提示这是唯一一次完整展示；
- 列表显示后四位、状态、首次兑换截止、兑换时间、完成时间和报告入口；
- root 可撤销或恢复访问。

## 错误处理

- 无效、过期、撤销的邀请码：统一提示，不建立会话。
- 同一邀请码并发首次兑换：数据库行锁和唯一 `guest_user_id` 绑定确保只创建一个有效访客；失败事务整体回滚。
- 重复提交：原子状态更新失败时返回 409“该内测任务正在生成或已经完成”。
- 队列已满：恢复 `RETRYABLE` 并返回现有 503 提示。
- 模型、图片或保存失败：任务显示现有短错误，状态恢复 `RETRYABLE`；访客可修改资料后重试。
- 服务重启：现有任务恢复扫描在退款处理之外同步通知内测状态服务，将中断任务恢复为 `RETRYABLE`。
- 报告过期或删除：邀请码仍可恢复受限会话，但只显示报告不可用，不恢复生成资格。

## 测试策略

### 后端自动测试

- 创建邀请码只返回一次原文，数据库只保存 hash 和后四位，默认截止时间约 7 天。
- 过期未兑换码、撤销码和错误码无法兑换。
- 首次兑换创建一个 `MATCHMAKING_TRIAL` 用户；重复及跨设备兑换复用同一用户并生成独立会话。
- 并发首次兑换最终只绑定一个访客。
- `requireUser` 拒绝内测角色；婚恋受限访问接受有效内测角色；撤销后已有会话也被拒绝。
- 普通注册邀请码不能兑换内测，内测邀请码不能注册账号。
- trial 从 `CLAIMED/RETRYABLE` 只能成功启动一个任务，不产生积分流水。
- 队列拒绝、worker 失败和重启中断恢复重试资格；成功后状态永久为 `COMPLETED`。
- 成功后再次提交被拒绝，再次兑换返回原 `reportId`；报告删除或过期后不恢复资格。
- 普通用户、root 全局读取及现有积分退款测试保持通过。
- 后台用户数和用户列表排除 `MATCHMAKING_TRIAL`，root 报告摘要显示内测别名。

### 前端与浏览器验证

- 未登录桌面和 390px 手机可进入婚恋页并看到邀请码入口，不出现登录弹窗强制拦截。
- 错误码提示、首次兑换、失败重试、任务轮询、成功跳转和跨会话恢复正常。
- 内测访客菜单不显示其他 USER 功能，直接调用受保护接口得到 403。
- 后台生成、唯一一次完整展示、复制、列表状态、撤销和恢复正常。
- root 全站报告显示内测别名，报告详情不出现越权删除。
- 完整 Maven 测试、前端生产构建、HTML/PWA/DAL/Android WebView/PDF 门禁、浏览器控制台和 `git diff --check` 通过。

## 不在本次范围

- 批量生成或导入邀请码。
- 短信、邮件或社交平台自动发码。
- 内测访客升级为正式账号或迁移报告。
- 永久报告、公开分享链接或绕过 30 天/数量保留策略。
- 为内测访客开放其他节目、积分、签到、通知或留言互动。
