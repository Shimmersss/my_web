# 婚恋报告 v3.5：免责声明 + 板块式报告 + 3D 评分饼图 + 伴侣画像插画

基于你 6 点反馈的实现方案：

## 1. 资料边界 → 免责声明
页面顶部"资料边界"块整体替换为**正式免责声明**区块，包含明确声明条目：
- 评分由服务器按公开规则确定性计算（年龄、身高市场通行曲线按性别区分），仅描述相亲市场供需参考，不代表、不衡量任何人的个人价值；
- 统计背景来自国家统计局 2025 年收入数据与民政部 2025 年婚姻登记数据，均为公开聚合数据，不是个人基准；
- 报告基于自愿资料与算法分析生成，仅供参考，不构成任何承诺；不做撮合、不预测成功率、不推荐具体对象；
- 不收集姓名、住址、单位名称、联系人；资料仅本人可见，保存 30 天自动删除，可随时手动删除；
- 伴侣画像插画由 AI 生成，纯属示意，与任何真实人物无关。

## 2. 自我介绍详细化
Mimo 合同中 selfIntro 从"三句话"改为 **150–250 字完整媒人话术版自我介绍**（可直接复制发给介绍人/贴到资料里），后端长度上限 280→560，前端章节标题改为"自我介绍"。

## 3. 动态评分展示（3D 饼图 + 点击查看）
- 评分总览改为 **SVG 伪 3D 立体饼图**（椭圆投影 + 侧壁厚度，纯 SVG/CSS 实现，不引入 echarts 等重依赖，符合低资源基线）：五个维度五种站点配色，各扇区显示占比；
- 交互：扇区 hover 高亮微弹出，**点击扇区或图例 → 图下方详情面板**展示该维度得分/满分、确定性依据、模型详细分析与"怎么做"（与 dimensionAnalysis 配对）；
- 图例同时显示每维得分。

## 4. 伴侣画像详细化 + GPT Image 2 插画（复用）
- 画像文字加详：portrait 上限 340→500（要求 180–350 字），whyMatch 260→350；
- **复用现有 `OpenAiImageClient.generate(prompt, "1024x1024", "low")`**（与 PPT、独立生图同一安全客户端与后台 Images 配置）；
- 表单新增勾选项（默认勾选）"生成伴侣画像插画（+N 积分）"，N 通过 status 接口动态返回 `imageCredit("low")`；
- 计费沿用 PPT 规则：创建时**同一事务预扣报告积分 + 插画积分**，模型/插画/存储任一失败整体幂等退款，不静默降级；
- 插画 prompt 由服务端用画像文字（截断 220 字）+ 固定约束生成：扁平温馨插画、柔和暖色调、无文字/水印、无可识别真实人像；
- 存储：base64 PNG 直接写入报告载荷 → `matchmaking_reports.report_payload` 从 TEXT 升级 **MEDIUMTEXT**（迁移仅 MySQL 执行，H2 的 TEXT 即 CLOB 无需改）；前端 `data:` URL 直接渲染，无需新增下载接口；30 天过期与删除接口自然覆盖。

## 5. 渠道打法 bug 修复
根因：模型把 channelStrategy 返回成对象 `{mainChannels, avoidPitfalls}`，后端 `text()` 用 `Map.toString()` 拼成了 `{mainChannels=...}` 原样显示。修复：
- 合同显式定义为对象（mainChannels / avoidPitfalls 两键必填）；
- 后端归一化兼容对象与纯字符串两种形态；
- 前端渲染为"主攻渠道"与"避坑提醒"两块；并对历史 v3 报告里已固化的 `{mainChannels=...}` 字符串做正则解析兜底。

## 6. 板块式报告框架
- 评分总览（3D 饼图）固定顶部；
- 其下改为**板块导航（chips）+ 详情面板**：自我介绍 / 市场解读 / 高频问答 / 伴侣画像 / 渠道打法 / 边界局限，点击板块进入完整内容（同时只开一个板块，移动端 chips 横向滚动）；
- 生成更细：MAX_TOKENS 8000→10000，各章上限上调（维度分析 3–5 句、行动建议 2–3 条、市场解读每项 2 句等），prompt 明确要求更细致。
