# 2026-09-11 全项目架构评估与首轮优化

状态：本地完成，未部署；分支 `codex/architecture-optimization`，基线 `6929b3b`。

## 范围与验收

用户要求先新建分支，再考虑整个项目的架构优化。使用独立 worktree，原 `codex/hunlian` 的关系探索未提交改动保留在原目录，不包含在本轮构建基线中；集成时须单独核对其 AI 客户端引用。

评估覆盖 Vue 请求/页面、Spring 模块依赖、四类生成任务、SQL/磁盘恢复、外部 CLI 和部署流程。保持单应用实例、2核/4GB资源边界。目标是可逐步演进的模块化单体。

首轮落实可独立验证的 Java 模块边界：

1. 将跨模块的后台聚合控制器移至 `admin`，账号 HTTP 聚合控制器移至 `account`（`/auth/me` 需要查询婚恋内测资格），使 `auth` 不再反向依赖业务模块。
2. 将文本/视觉和图片 provider 客户端归入 `ai`；删除经全库引用检查确认无调用的旧段落翻译入口，以及 PPT 构造函数中从未使用的 LLM 依赖。保留当前文本、视觉、生图协议、重试和预算。
3. 演示素材库接收自身定义的发布数据，避免依赖可变 `PptGenerationSession`，消除 PPT 与生图模块的双向依赖。
4. 增加仅测试依赖的 ArchUnit：检测顶层包循环依赖、基础层反向依赖与业务层调用控制器，接入现有 Maven test。

协议回归实际复现一项既有问题：RestClient 的默认鉴权头会在请求级头之后合并，仅调用 `headers.remove` 无法阻止另一 provider 的默认凭据随请求发送。将修复纳入本轮公共客户端边界：构造独立客户端副本时清理默认 provider 鉴权头，每次请求再按自身配置赋值；保留共享 Bean 的原配置、超时与 Content-Type。

本轮不改任务状态机、计费事务、SQL schema、文件格式、资源阈值、前端交互或部署脚本；高风险优化给出独立验收要求与顺序。

## 风险、验证与回滚

- 包移动可能影响 Spring 扫描、构造注入及跨模块调用：先用架构测试重现现有循环，再定向回归，最后 Maven clean test 清除旧 class 后全量验证。
- 客户端移动保留在 `com.web.backen` 扫描树；以受控 HTTP 响应校验协议、认证头、模型/提示词和视觉输入；不调用收费模型。
- 素材发布契约检查落盘元数据、重复发布、真实 PNG/JPEG 预览、归属、root只读审计及源任务清理后仍可读。
- Java 改动不涉及 SQL 语义/迁移；现有 MySQL 集成测试是否执行须如实记录，不以 H2 冒充 MySQL 验证。
- 更新共享架构说明、文档索引、本地 AGENTS/WORKLOG，做最小 diff、链接与敏感信息审查。
- 回滚为撤销本轮源码/测试依赖/文档改动并重新 clean 构建，无数据迁移；未授权生产发布。
