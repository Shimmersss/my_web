# 制作与验收规则

## 1. 主题选择与母版

1. 读取本目录规范、实际牌义 JSON、该牌基础图及现有候选 manifest。先用图像查看工具打开实际输入，不能只凭牌名或历史观察生成。
2. 查 `production-prompts.json` 的对应 card/theme。跨主题至少改变场景结构、主体服饰/材质、构图、配色四项中的三项；仅换色或加强光效不合格。五主题并排，120px 宽仍应能区分。
3. 不把基础牌所有配角照搬到每个新主题。`identityAnchors` 定义必留象征；例如其他牌原图附带的月亮不是必须全系列保留，太阳以太阳为主、星星以八芒星为主。人物数量、关键物件数量及接触逻辑优先于装饰。
4. 主题之间可以换姿态和镜头；同一主题选定母版后，拆层阶段不得随意换姿态。保持同一牌可辨的年龄感与身份特征；人体、动物四肢结构可靠。
5. 一次一主题一张完整单卡。母版 1024×1536，PNG 原件保留；不将五卡拼图裁切交付。标题编号不交给生图，页面用真实文本排版。
6. 人工检查核心象征、数量、脸手、相互接触、反射、遮挡、过曝与边框后，记录为 `selected-master`。这是执行者的制作选择，不等于用户审美确认。无需每图再向用户索取许可；需要审美偏好时展示具体对照，保持独立工作推进。
7. 采用母版若发生主体重绘漂移，必须重新做对照并记录版本，不能用“提取图”掩盖新的设计。月亮现有四张候选默认复用，发现已知甲壳形态问题时记录并另存修订版。

## 2. 图层合同

| 文件 | 内容与透明度 | 初始深度 |
| --- | --- | --- |
| `assets/background.png` | 完全不透明环境，清除所有独立层物件、外框及需移除的投影，补全遮挡区 | −0.08 |
| `assets/subject.png` | 主体与必须保持连接的物件，真实 RGBA；主要空隙也透明 | 0.14 |
| `assets/effects.png` | 少量前景，不遮脸/手/牌义核心，真实 RGBA | 0.28 |
| `assets/text.png` | 固定窄边框、角饰；内部透明，不含生图文字 | 0 |
| `assets/lineart.png` | 从最终主体派生的同坐标黑线白底，驱动局部闪光 | 随主体 |

所有层共享 1024×1536 画布、原始坐标与安全区。默认保守起点 `subjectScale=1.0`、`effectsScale=1.05`、`foil=0.30`；逐牌单另有建议时采用逐牌值；这些为试调起点，不是每牌必须相同的最终值。按极端倾斜检查后填写实际参数。

- 先读取 [逐牌制作单](README.md#逐牌制作单) 与JSON的 `productionDetail`，再填写该主题 `layerPlan`：各物件唯一归属、连接组、反射/投影归属、alpha 类型。提示词中的连接组是约束，不能同时把相同地面或配角分给主体与背景。需要跨多组处理时先明确归属再调用工具。
- 手与持物、人与骑乘动物、车马缰绳、壶杯连续水流、绳与树枝保持同组，禁止图层平移造成脱离。
- 倒影属于水面，不能任意随主体漂浮。接触处不能可靠重现时，合并相关区域或降低额外视差并记录原因；仍保留前景/背景层次，不以空壳工程代替分层。
- 外框只显示一次。使用独立框时，背景、主体不能残留烘焙框；完整母版仅用于静态回退，不叠加同一套主体。
- 空间深度不等于骨骼动画：2D 海灵/人物图层不能声称已完成完整立体建模。需要多独立主体或真实浮雕时用技能的 relief 模式另作工程，明确新增测试，禁止伪造完成。

## 3. Alpha、线稿与失败修复

1. 请求真实透明 RGBA，先检查图像通道，再分别叠在黑、白及中灰底上看边缘。RGBA 通道存在不等于透明正确；烘焙棋盘不能通过。
2. 查看 alpha 覆盖率、空隙、半透明边缘和小物件，但不使用深海范本某一覆盖率作统一门槛。白发、珍珠、冰雪不能误删；黑兽不能因黑底被删。
3. 若工具持续画棋盘，优先编辑该层为与主体不冲突的纯色背景，再精确色键去底、抑制溢色。绿色主体/叶片不能使用绿色键；更换与目标分离的背景色。保留原图、键色、阈值和修复脚本。
4. 纯黑底提取仅适合独立发光水母/微光等可加色前景，不适合有黑色实体或复杂透光材质的主体。半透明天使不得直接亮度键抠掉暗部身体；单独验证保留柔边。
5. 线稿从最终 alpha 主体派生，去掉透明区和低可信软边，稀疏阈值单图调校；禁止独立生图线稿或使用旧版本轮廓。
6. 零视差合成与采用母版并排检查。提取差异若影响身份/形态，回到母版选择步骤；底图清除主体后不能留第二只兽、第二张脸或月轮影子。
7. 范本 `finalize_layers.py` 可参考算法，但 `prepare_layers.py`、`refine_mattes.py` 与旧 alpha 报告是历史实验。禁止运行这些旧脚本覆盖最终资产。

## 4. 材质与动效

- 材质图案由主题目录的 `surfaceMotif` 指定。海洋可贝母、沙岩可磨砂铜、冰雪可细银、纸艺可纸纤维；不能每张都套同一条彩虹。
- 箔光必须随观看角度变化。线条闪光与金属条纹分开、稀疏遮罩，保留印刷细节；不靠满屏发光遮盖失败。
- 至少提供珠光、银箔、烫金、原画四种可用切换；默认材质按该牌选择。选择“原画”仍可保留卡体交互，但关闭额外强箔光。
- 默认只选一种主运动：细光呼吸或极轻前景漂移；允许再加少量从属动效。水滴不逆流、狮嘴不动、马腿不分拆、天平不失衡、四季圆章与世界四角肖像不旋转。
- 几何圆环可另加无肖像内环缓转；不得旋转整幅牌面模拟局部动画。静态图上的光波不是已实现动画，需在 manifest 写 `implemented` 或 `planned`。
- 低动态偏好关闭自动转动、时间驱动微粒及登场动画；拖动/键盘仍可用。未来卡册采用静态缩略图，当前原型一次只激活一张 WebGL 卡，不开 110 个上下文。

## 5. Blender 与 Three.js 工程

后续执行时读取 `~/.codex/skills/RuiC-card-skill/SKILL.md` 及其引用；技能路径失效先定位，不自行发明 API。缺必要环境主动安装官方来源版本并校验，不能跳过 Blender 改交 CSS 截图。

```sh
# <project> 替换为实际绝对主题工程目录；不可原样执行占位符。
python3 ~/.codex/skills/RuiC-card-skill/scripts/validate_assets.py <project>
python3 ~/.codex/skills/RuiC-card-skill/scripts/run_pipeline.py --project <project>
node ~/.codex/skills/RuiC-card-skill/scripts/verify_web.mjs <project>
PORT=4188 node <project>/web/server.mjs
```

运行前确认 `python3` 对应环境有 Pillow 等依赖。深海工程 `.venv` 有 Pillow/numpy/scipy，`tools/Blender.app` 是已核验的 Blender 4.5.3 ARM64。新主题可共享同一工具安装，通过实际脚本支持的参数/路径调用；不向每个主题复制数百 MB 安装包。不要把模型缓存、node_modules、下载包纳入交付或 Git。

- 模板起点为深海 `card-config.json`；替换标题、描述、版号、各资产路径、默认 finish 和实测参数。不能遗留“深海幻月”字样或“白相”模板品牌。
- 每次重新运行 pipeline 可能覆盖网页定制，运行后执行 `deploy/embed-flashcards.py` 恢复“月下收藏库”品牌（“月下会客厅”已于 2026-10-13 停用）和手机标题独占行规则，再执行验证。修改 app.js 必须重新 bundle；依赖用锁文件。
- 保存 `card.blend`，所有图片 packed；播放时间线可见转卡。图像平面保持对象 X=90° 未应用旋转；视差按卡根坐标计算，不能误用 glTF 转换后的局部轴。
- GLB 必须有真实卡体几何与 `web_front/web_edge/web_back/web_gold` 材质角色，不能用截图冒充模型。
- Blender 视差/箔光节点在网页重建为 GLSL；glTF 不完整传递这些节点，两端不保证逐像素一致。交付说明必须保留这个边界。
- 清除/切换卡片时释放纹理、材质、几何、监听与 RAF；页面隐藏暂停时间更新。若新增卡册必须单独测内存与加载，不把单卡测试外推为全站通过。

## 6. 每主题质量门

| 阶段 | 必查 | 完成证据 |
| --- | --- | --- |
| 母版 | 核心象征、人数/动物数、脸手、三项主题差异、120px可辨 | 母版原件、对照、人工结论 |
| 分层 | 同画布、真alpha、黑白灰底边缘、空隙、连接、水面倒影、无重影 | 校验 JSON、合成图、边缘检查图 |
| Blender | 打包图片、参数可改、真实几何、渲染与侧边 | card.blend、hero.png、结构报告 |
| 网页 | 技能全套检查，实际 WebGL 非回退，拖动/翻面/缩放/键盘/每滑杆/四材质/下载 | report.json及截图 |
| 视觉 | 正面及左右倾斜、上下极值、画面不拉伸漏底；变化后重新核对 | 人工审查记录，不能只凭ready标志 |
| 布局 | 桌面、390px、320px，标题横排、控件可达、无横向溢出 | 三尺寸截图与结果 |
| 动态 | reduced-motion 确实停动，静止材质仍可读；无错误及失败资源 | 自动检查和实际截图 |
| 移交 | 哈希、实际输入、完整提示词、图层归属、已做/未做、路径可用 | manifest、README、WORKLOG |

自动检查通过仍须人工看图。深海范本已证明“无横向溢出”仍可能把标题挤成逐字竖排，不能只看数字。

浏览器网页桌面验收不等于 Android 验收。用户后续要求接入本站/GeckoView 时，再按 Android 工作流在模拟器或设备核对触摸、WebGL、下载与生命周期；未做要明确标记，不自动发布 APK。

## 7. 命名、状态与回退

其他21牌基础工程使用 `theme-01/`，不覆盖基础原画；按 [月亮五样本指南](moon-sample-guide.md) 补齐分层。新主题路径：`output/tarot-progression/v2/major-NN/theme-02/` 至 `theme-05/`。主题 ID 稳定，不因中文名或等级展示顺序变化重命名；manifest 分开记录主题 ID 与建议槽位。

每主题保留 `source/` 原始工具结果、`masters/master-v01.png`、`assets/`、`card-config.json`、`generation-prompts.json`、`manifest.json`、处理脚本、`card.blend`、`renders/`、`web/`、`verification/`、README。失败候选不覆盖采用版；新增修订递增版本并记录替代关系。

月亮既有目录继续保留：深海工程在 `v2/deep-sea-holo/`，四主题母版在 `v2/major-18/`。在状态记录中指向现有路径，不为统一目录而搬动、覆盖或重复生成。新目录规则用于后续新增成果。

状态依次记录：`planned → generated-candidate → selected-master → layers-verified → local-holo-verified`；失败用 `needs-rework`，记录具体原因。`userReview` 与技术状态独立。发布仅在明确授权和完成站点验收后记录，不新增一个假“已上线”状态。

原件、输入 SHA256、完整最终提示词、工具、输出文件、尺寸/通道、alpha统计、版本、实际参数、测试报告路径必须齐全；不要写将来的输入为实际输入。图片工具若有调用ID则记录，没有就填 null。

失败只返工相关阶段。工具额度/凭据阻断时记录真实错误与续作位置，继续无依赖的文档/校验；不得换未经授权的付费服务或假装生成。未获部署授权时交付本地结果即可。回退保留旧母版、基础卡与账户数据；美术回退不删除等级/积分流水。

## 8. 月亮返修规则升级

承重地形必须保留至自然遮挡或出血边界；薄石条、小水圈不是完整支撑。若出现双桥面、地台缺口、纹理边缘被拉伸，先修图层归属与边缘覆盖，不能只减深度遮盖。背景清底范围应与主体完整连接组完全一致。实际提示词必须自首次调用完整保存；规范提示词不冒充实际调用记录。五主题的主题内容、画内元素和材质共同变化，但同主题内部拆层保持母版一致。
